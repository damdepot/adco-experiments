# NaiveLLM — single-shot LLM rewriter baseline

The deliberately simple baseline: copy an application, send its driver + entry
file to an LLM **once** at temperature 0, write back whatever comes back. No
profiling, no iteration, no feedback from the database.

Two layers use the same CLI: the **app layer** (TPC-C / Smallbank driver +
`tpcc.py`/`main.py`) and the **query layer** (`db_app.py` compiled from
`query*.sql`, used by Stats and TPC-H).

TPC-C runs with a prompt generated by an offline repair loop
(`prompts/selected.txt`), not the unguided prompt. The loop starts from the
generic `prompts/basis.txt`, rewrites, runs the four correctness gates, and
revises the guidance from the failures until it passes twice. The file must
exist before the arm runs; an **empty** file is valid and means the model
produced no guidance. Smallbank is deferred: it keeps the unguided default and
has no correctness oracle yet.

## Layout

| Path | Purpose |
|------|---------|
| `src/cli.py` | CLI: copy tree, select files, one LLM call, apply + syntax check |
| `src/rewrite.py` | file selection, prompt assembly (task + optional guidance + rules), `### FILE:` parsing |
| `src/query_codec.py` | `compile` `query*.sql` → `db_app.py`; `decompile` back to SQL |
| `prompts/` | generic seed (`basis.txt`) plus the generated `selected.txt` and `selected.meta.json` |
| `tests/test_rewrite.py` | prompt/parse/select-file unit tests |
| `venv/` | this baseline's venv (`uv`), hash-pinned by `.venv_hash` |

Deps are only `google-genai` and `python-dotenv`.


Default model is `gemini-3.5-flash-lite` (`MODEL` env, or the CLI `--model`).

## Direct CLI

```bash
cd baselines/NaiveLLM
venv/bin/python -m src.cli \
    --source-dir ../../workload/apps/tpcc --output-dir /tmp/rewrite-tpcc \
    --db postgres --model gemini-3.5-flash-lite \
    [--prompt-file prompts/basis.txt]
```

What it does:

1. Deletes and re-copies `--source-dir` (skips `.git`, `venv`, `__pycache__`).
2. Selects writable files: `drivers/postgresdriver.py` (or `mysqldriver.py`), plus
   `tpcc.py` / `main.py`; for query layer, `db_app.py`. Schema files are read-only
   context. Missing driver → exit 1.
3. Builds one prompt and calls the model once at `temperature=0.0` (override with
   `--temperature`), `max_output_tokens=65536`.
4. Parses `### FILE: <relpath>` blocks, refuses paths outside the changed set
   (`safe_target`), writes them, then `py_compile`s each; any file that fails to
   compile is restored to its original bytes.
5. Prints `files changed: N, restored: M`; exits 1 if nothing usable was produced.

An empty `--prompt-file` (or one with only whitespace) is treated as no guidance,
so the prompt stays byte-identical to the unguided baseline.

Artifacts land next to (not inside) the output dir: `llm_prompt.txt` (exact
prompt sent), `llm_response.txt` (raw model output), and `smoke.log` (rewrite
smoke run, written by the app-layer driver).

## Query layer (Stats, TPC-H)

```bash
cd baselines/NaiveLLM
venv/bin/python -m src.query_codec compile   --input-dir <query dir> --output-dir <dir>
venv/bin/python -m src.query_codec decompile --input-dir <dir>       --output-dir <query dir>
```

`compile` packs `query<N>.sql` in numeric order into one `db_app.py` (plus
`schema.sql` copied as context); `decompile` extracts `QUERY_<n>` constants back
to `query<N>.sql`. `run/stats/run_naive-llm.sh` and `run/tpch/run_naive-llm.sh`
drive the Compile → Rewrite → Decompile → Verify pipeline through
`scripts/common/query_layer/exp2_Baselines/runExperiment2-NaiveLLM.sh`, then run
the workload.

## App-layer runs

```bash
./run/tpcc/run_naive-llm.sh                  # generated prompt (selected.txt)
./run/tpcc/run_naive-llm-robustness.sh 10    # 1 measured re-check + 10 fresh rewrites
./run/smallbank/run_naive-llm.sh             # unguided default (Smallbank search deferred)
```

Knobs (defaults are the reported TPC-C arm):

| Var | Default | Notes |
|-----|---------|-------|
| `ARM` | `naive-llm` | result dir `results/tpcc/<ARM>` |
| `NAIVE_REWRITE_ROOT` | `out/app_layer/NaiveLLM-results` | rewritten tree root |
| `PROMPT_FILE` | `baselines/NaiveLLM/prompts/selected.txt` | hard-fails if missing; empty = unguided |
| `MODEL` | `gemini-3.5-flash-lite` | |

`run_naive-llm.sh` refuses to start until the generated prompt exists:

```
ERROR: missing selected prompt .../selected.txt
Run ./run/tpcc/run_prompt_search.sh first (an empty file is valid).
```

The shell driver rewrites into `<root>/Rewrite/<dbms>/<bench>-NaiveLLM`, runs a
smoke pass (fails on `Traceback`, on TPC-C transaction errors other than
deadlocks, or on >5% Smallbank errors), then measures.

## Generated-prompt workflow

```bash
./run/tpcc/run_prompt_search.sh          # repair loop -> prompts/selected.txt
./run/tpcc/run_naive-llm.sh              # measure the frozen prompt
./run/tpcc/run_naive-llm-robustness.sh   # re-verify N fresh rewrites
```

Optional args: `[dbms=postgres] [model]` (the benchmark is implicit).

The loop:

```
prompt = prompts/basis.txt
rewrite -> four gates -> PASS twice? freeze : (failures + diff -> revise prompt)
```

| Step | Behavior |
|------|----------|
| Gates | static, smoke, reads, invariants (`run_verify.sh`) on the 1-warehouse verify seed |
| Success | base PASS plus `CONFIRM_RUNS` (3) confirmation rewrites at `CONFIRM_TEMPERATURE` (default 0), **all** of which must PASS; one lucky sample is not enough |
| Nondeterminism | Vertex is not deterministic even at `temperature=0`, so a single PASS is not treated as stable |
| Revision | `improve_prompt.py` gets the failing gates, deduped smoke errors (timestamps stripped, repeats counted) and the offending diff, and returns guidance only |
| Models | rewrite and confirmations use the arm model at temperature 0; `IMPROVER_MODEL` (default: same) and `IMPROVER_TEMPERATURE` (default 0.2) drive only the prompt revision |
| Generality | bullets must not name this benchmark, its tables, transactions, columns or literals; violations are re-asked, then dropped |
| Caps | `MAX_ITERS` (8), `CONFIRM_RUNS` (3), 25 bullets, 4 KiB; a repeated prompt exits `stalled` |
| Freeze | `prompts/selected.txt` + `prompts/selected.meta.json` (model, iteration history, prompt `sha256`) |

Scratch (every rewrite, `verify.json`, `prompt.meta.json`, `history.tsv`) goes
to `out/app_layer/NaiveLLM-search-results/` — never `results/`.

The frozen prompt is shared by every workload, so it is written and linted as
general SQL/driver guidance, not TPC-C advice.

## Robustness (TPC-C)

```bash
./run/tpcc/run_naive-llm-robustness.sh [runs=10] [dbms=postgres] [model]
```

Each run is: rewrite with the selected prompt → verify that tree → record.
No run 0, no measured-artifact check, no separate performance seed.

| Path | Contents |
|------|----------|
| `results/tpcc/robustness/naive-llm/latest.json` | summary consumed by the report |
| `out/app_layer/robustness/naive-llm/<ts>/summary.json` | same, timestamped |
| `out/app_layer/robustness/naive-llm/<ts>/summary.md` | run table + headline |
| `out/app_layer/robustness/naive-llm/<ts>/rNN/` | rewrite, verify log/JSON |

`latest.json` holds `runs_completed`, `counts` (pass/fail/warn/unverified),
`status`, `failures`, and the per-run list. It verifies with a small
`tpcc_verify_seed` (default **1** warehouse), created once and reused; the
performance arm still measures on the full `tpcc_seed`. `RESEED=1` rebuilds the
verify seed.

Each iteration prints `run i/N: PASS|FAIL|UNVERIFIED`; the verify log under
`rNN/verify.log` has the four-gate detail. The whole verify child is capped at
`VERIFY_TIMEOUT` (default 300 s); a hung run becomes `UNVERIFIED` and the loop
continues. `VERBOSE=1` dumps the rewrite log.

## Correctness in reports

`./run/tpcc/run_reports.sh` adds a `## Correctness` table and a Correctness
column to both performance tables. Arms with a robustness summary use it
(`PASS 9/10`, run counts); arms without one fall back to the single-run
`results/tpcc/verify_<arm>.json` and show `1-run PASS`. WARN shows as SUSPECT;
no check shows UNVERIFIED.

## Prompt files

| File | Role |
|------|------|
| `basis.txt` | generic seed the loop starts from; not tuned to a benchmark |
| `selected.txt` | generated prompt, frozen with `selected.meta.json`; may be empty |

`selected.txt` is an artifact: never edit it by hand. `selected.meta.json`
records the model, the per-iteration gate results and the prompt `sha256`.

## Tests

```bash
python3 baselines/NaiveLLM/tests/test_rewrite.py    # prints "ok"
```

Covers response parsing, path safety, file selection, that the default prompt is
unchanged, guidance placement, and that prompt files are non-empty and contain
no markdown fences or `### FILE:` lines.

## Notes / limitations

- One shot, temperature 0; no retries, no profiling, no DB feedback.
- No schema changes, no new files, no new dependencies (enforced by prompt, not code).
- Validation is syntax-only (`py_compile`). Runtime failures are caught by the
  app-layer smoke run; TPC-C correctness by `run_verify.sh`.
- `naive-llm-aggressive` is retired for TPC-C: there is one `naive-llm` arm. The
  Smallbank wrapper still exists (`run/smallbank/run_naive-llm-aggressive.sh`)
  and is deferred until Smallbank gets a correctness oracle.
- `results/tpcc/naive-llm` numbers recorded before the prompt switch are stale
  (unguided) and must be re-run with `./run/tpcc/run_naive-llm.sh`.
- The prompt was repaired against TPC-C gate failures, so its wording is shaped
  by that workload even though every rule is written to be generic. Label it
  that way, not as an out-of-the-box result.
