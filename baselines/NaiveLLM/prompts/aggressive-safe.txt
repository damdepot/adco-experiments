- Optimize for speed, but prove equivalence before emitting: if you cannot show a rewrite preserves behavior, keep the original code.
- Replace N+1 queries and per-row lookups with set-based queries.
- Batch a multi-column key by constraining each key column separately (one `= ANY(%s)` / `IN` list per column) and re-match the exact key in code; never build composite row/tuple values for comparison.
- Never narrow a combined query's filter to one scalar value when per-row values can differ; keep it equivalent over the union of all per-row key values.
- When lookups are combined, the database may return matching rows in any order: map each result back to its input by its full key tuple, never by position.
- Every bound value must match the declared type of the column it is compared with, per the provided schema; when a column's type is narrower than the bound value, cast the value to the column's type.
- Keep the original missing/empty-row path, commit/rollback placement, transaction boundaries, and row-write count; never silently skip a row so the write set shrinks.
- Send values through the driver's own binding; never build statements or bulk data by hand.
- Change no schema, public signature, ordering, or null/type semantics.
- Prefer pushing filtering, aggregation, and joins into SQL and selecting only the columns the caller needs.
- Replace per-row writes with bulk writes (executemany, multi-row INSERT, COPY) while preserving the exact write set and commit/rollback placement.
- Reuse connections, cursors, and prepared statements; cache read-only lookups within a transaction.
- Optimize the dominant transaction's critical path first without starving the others.
